## Provider C prospective qualification gate

External provider C cannot be selected until a prospective preflight verifies:

1. legitimate operator/account access from the researcher's jurisdiction;
2. sandbox/test credentials obtainable legitimately;
3. no real-money requirement;
4. the required mutation API is accessible in test/sandbox mode;
5. an authoritative observation/reconciliation API is available;
6. retry/idempotency semantics are documented sufficiently.

Only after every preflight condition passes may provider-specific semantics
reconnaissance or implementation begin. Provider C selection and the final
cross-provider protocol are global pre-data decisions: paper collection cannot
begin in GitHub, Google Sheets, Provider C, or any other external Study 2
environment while Provider C remains TBD. Results from GitHub or Google Sheets
therefore cannot influence Provider C selection.

Provider C's identity, semantics contract, scenario catalogue, manifest,
evaluator, and any provider-specific analysis amendment, together with the final
cross-provider Study 2 protocol, **MUST** be frozen and hostile-audited before
**ANY** Study 2 paper observation is collected in GitHub, Google Sheets,
Provider C, or any other external Study 2 environment.
