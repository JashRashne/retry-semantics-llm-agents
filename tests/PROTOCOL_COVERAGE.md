# Implemented invariant coverage

This implementation deliberately covers only invariants enforceable at the
deterministic environment, hidden-world construction, Exact Replay, evaluator,
canonical Regeneration-context, and one-call provider-adapter layers.

| Invariant | Current enforcement |
| --- | --- |
| INV-1 | Construction accepts one frozen M object plus explicit canonical bytes/hash, checks their coherence before dispatch, and gives that same immutable M to all four arm starts. The Regeneration context consumes the stored original assistant message, including its exact raw JSON argument string, and validates its single structured call against M without replacing it. The trace schema reserves that raw string separately; original-generation capture and full trace linkage remain pending. |
| INV-2 | Each hidden-world snapshot is serialized once and cloned into byte/hash-identical, independent policy-arm starting environments; family validation checks both pairs before recovery, and Exact Replay tests prove P1 execution leaves the P2 sibling unchanged. |
| INV-3 | The pure Regeneration context builder accepts only the exact user task, frozen M, and stored original assistant message; it fixes the complete four-message sequence and two-tool catalog. The new pure boundary helper and Groq mapper prove that H0/H1 yield equal canonical bytes/hashes, equal provider-neutral requests, and equal Groq payloads under the same call configuration while authoritative state hashes differ. Original-generation capture remains pending. |
| INV-4 | Exact Replay has no model parameter, callback, interface, or dependency and its immutable result fixes `additional_llm_calls=0`. Later full traces will reconcile this with lifecycle instrumentation. |
| INV-5 | The canonical context has an exact closed structure and is constructed without a hidden-world or environment input. The provider-neutral helper accepts only that context plus call configuration, and the Groq mapper accepts only the resulting request. Hostile serialized-payload tests scan for hidden labels, execution flags, evaluator classifications and IDs, mutation/state fields, and actual family state hashes. Later runner/trace integration must enforce use of this boundary. |
| INV-6 | Exact Replay passes the post-termination authoritative `TicketState` to the existing deterministic evaluator; no model claim or observation enters evaluation. |
| INV-7 | Family construction requires the fresh empty authoritative state, captures it without mutating the source, and creates every branch/arm by snapshot deserialization. |
| INV-8 | Ticket and immutable event are published atomically; Exact Replay requires one newly committed event, returns its ID, and verifies that event's frozen bytes/hash and RECOVERY provenance. Events remain state-reconstructable. |
| INV-9 | The local executor has no retry/network layer; Exact Replay contains one executor call. The Groq adapter now constructs the official SDK with `max_retries=0`, uses no retry loop, and tests one SDK call on both success and timeout. Provider-internal behavior outside the SDK boundary must still be accounted for in experiment traces. |
| INV-10 | Exact Replay verifies SHA-256 and representation equality before dispatch, then passes the caller-supplied `serialized_original_request` bytes object directly to the executor. A capture test proves object identity; parsing for evaluation occurs only after dispatch and is never reserialized. |
| INV-11 | Timeout, authentication, rate-limit, connection, unrelated HTTP 400, 5xx, and structurally malformed-response failures have explicit provider/infrastructure exception types. Groq rejected-generation behavior is recognized from either explicit `tool_use_failed` or the documented code-absent `invalid_request_error + failed_generation` form. Readable evidence raises the provider-neutral `ModelRejectedGenerationError`, which is a `ModelBehaviorError` and deliberately not a `ModelProviderError`. Structurally readable successful completions—including no call, multiple calls, wrong tool names, and invalid argument JSON—remain `ModelResponse` data. Full experiment exclusion classification remains pending. |
| INV-14 | Each request contains the complete immutable message/tool value. `GroqModelClient.complete(request)` submits that complete array directly and retains no chat/session/history state; fake-client tests assert one explicit call. Cross-trial trace canary reconciliation remains pending. |
| INV-15 | Construction rejects non-`create_ticket` M before dispatch and verifies H1's one ticket exactly matches M. Upstream scenario eligibility/original-generation logging remains pending. |
| INV-16 | The exact system prompt, four-message order/fields, catalog order, protocol tool descriptions, and both complete schemas are single frozen definitions. Groq mapping wraps each frozen catalog entry directly as a function tool without altering descriptions or parameters and preserves message order/content/linkage. Original-generation reuse remains pending. |
| INV-17 | A successful Exact Replay result fixes attempted/executed recovery calls at one, the implementation has no loop or fallback, and dispatch-delta plus injected-error tests cover success and failure boundaries. The Regeneration budget remains pending. |
| INV-18 | The builder has no timing input and the canonical logical context permits only frozen messages/tools. Transport timeout exists only on `GroqModelClient` construction and cannot enter `ModelRequest` or the context hash. Hostile request-payload tests scan timing and state metadata; runtime diagnostic trace separation remains pending. |
| INV-20 | Golden evaluator fixtures cover every primary class, overlaps, precedence, and exact matching; Exact Replay adds the H0 `CORRECT` and H1 `DUPLICATE_EFFECT` state oracles. |
| INV-21 | The adapter preserves every returned tool call in provider order, retains the exact raw `function.arguments` string, strictly detects malformed JSON, duplicate keys, non-standard constants, and non-finite numbers, and records parse failure without repair or a second call. Wrong tool names, zero/multiple calls, combined content/calls, and empty/null content are preserved. Groq rejected-generation behavior is recognized from either explicit `tool_use_failed` or the documented code-absent `invalid_request_error + failed_generation` form; readable evidence is recursively frozen without repair, while other provider failures remain infrastructure/provider errors. Every tested success, rejection, and error path performs one SDK invocation with no retry. |
| INV-22 | Model-visible CREATE/LIST projections contain only frozen visible fields. |
| INV-24 | H0 and H1 originate from one captured initial snapshot; each post-ambiguity snapshot is cloned twice without redispatch. Executing both P1 arms leaves both P2 arms and all stored initial/world snapshot bytes unchanged. |
| INV-25 | The Exact Replay result records the one attempted/executed action, observation, new commit-event ID, termination reason, final snapshot/hash, and evaluation. Complete lifecycle events and schema-valid arm traces remain pending. |
| INV-26 | Exact Replay rejects disagreement among the immutable frozen M object, explicit bytes, and explicit hash before dispatch; its recovery event retains those exact bytes/hash. Regeneration preserves the supplied stored assistant message and raw `arguments_json`, strictly parses it, and rejects disagreement among raw arguments, stored parsed arguments, executable M, tool name, or original call ID. The Groq mapping now places that exact stored string in `function.arguments` without parsing/reserializing and preserves the ambiguity tool-call linkage. Original-generation capture and full-trace coherence remain pending. |
| INV-27 | Model configuration is a separate immutable value. Tests prove a seed change changes only model-call configuration/provider fields, not canonical context bytes/hash, and prove identical H0/H1 contexts plus one shared configuration yield equal provider-neutral requests and Groq payloads. Matched multi-call seed derivation and trace enforcement remain pending with Regeneration execution. |

INV-4–5, INV-9, INV-11, INV-14–18, INV-21, INV-25–27. Mocked provider tests
