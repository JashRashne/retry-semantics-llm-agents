# Implemented invariant coverage

This coverage map targets experiment version `primary-create-v1.2` while retaining
schema version `trace-schema-v1`. This implementation deliberately covers only invariants enforceable at the
deterministic environment, hidden-world construction, Exact Replay, evaluator,
canonical Regeneration-context, bounded Regeneration executor,
original-generation, frozen scenario catalog, pure engineering-manifest
materialization, one-scheduled-trial orchestration, serial 16-slot engineering
execution, recovery-arm trace serialization, atomic local persistence, and
one-call provider-adapter layers.

| Invariant | Current enforcement |
| --- | --- |
| INV-1 | The original-generation boundary performs one explicit model call and, only for an eligible response, creates one immutable `FrozenExecutableRequest`. The one-trial orchestrator feeds that same M object/bytes/hash directly into one family construction, which gives it to all four arm starts. One shared Regeneration context consumes the simultaneously frozen original assistant message, including its exact raw JSON argument string, without replacing it. The engineering ledger links every eligible slot to exactly four unique H0/H1 P1/P2 arm traces, all of which persist the same frozen M identity. |
| INV-2 | Each hidden-world snapshot is serialized once and cloned into byte/hash-identical, independent policy-arm starting environments; family validation checks both pairs before recovery, and Exact Replay tests prove P1 execution leaves the P2 sibling unchanged. |
| INV-3 | The pure Regeneration context builder accepts only the exact user task, frozen M, and stored original assistant message; it fixes the complete four-message sequence and two-tool catalog. Eligible original-generation output supplies those artifacts directly. The Regeneration executor consumes that context object for its first request without reconstruction. Tests prove that H0/H1 yield equal canonical bytes/hashes, equal first provider-neutral requests, tools, derived seed, and sampling configuration while authoritative state hashes differ; later request histories diverge only after a model-selected state-revealing read. |
| INV-4 | Exact Replay has no model parameter, callback, interface, or dependency and its immutable result fixes `additional_llm_calls=0`. Engineering-family validation rejects nonzero Replay model counts, and Replay traces contain no model-invocation lifecycle event. |
| INV-5 | The canonical context has an exact closed structure and is constructed without a hidden-world or environment input. The provider-neutral helper accepts only that context plus call configuration, and the Regeneration executor uses this boundary directly. Hostile serialized-payload tests scan the actual first executor requests for hidden labels, execution flags, evaluator classifications and IDs, mutation/state fields, and actual family state hashes. Full runner/trace leakage reconciliation remains pending. |
| INV-6 | Exact Replay and Regeneration pass the post-termination authoritative `TicketState` to the existing deterministic evaluator; no model claim or observation enters evaluation. Behavioral rejection and text-stop tests cover H0/H1 state-so-far evaluation. |
| INV-7 | Family construction requires the fresh empty authoritative state, captures it without mutating the source, and creates every branch/arm by snapshot deserialization. |
| INV-8 | Ticket and immutable event are published atomically; Exact Replay and valid Regeneration CREATE actions return newly committed event IDs and verify RECOVERY provenance. Regeneration READ and invalid-action tests prove that no mutation event is fabricated. Events remain state-reconstructable. |
| INV-9 | The local executor has no retry/network layer; Exact Replay contains one executor call. The Groq adapter constructs the official SDK with `max_retries=0`; original generation and Regeneration call `ModelClient.complete` only at explicit protocol opportunities. Recording-client tests prove no retry after stop, invalid output, budget rejection, rejected generation, or provider timeout. Provider-internal behavior outside the SDK boundary must still be accounted for in experiment traces. |
| INV-10 | Exact Replay verifies SHA-256 and representation equality before dispatch, then passes the caller-supplied `serialized_original_request` bytes object directly to the executor. A capture test proves object identity; parsing for evaluation occurs only after dispatch and is never reserialized. |
| INV-11 | Timeout, authentication, rate-limit, connection, unrelated HTTP 400, 5xx, and structurally malformed-response failures have explicit provider/infrastructure exception types. Groq rejected-generation evidence becomes an immutable pre-treatment behavioral result during original generation. During Regeneration the executor preserves the readable exception evidence, terminates as `model_rejected_generation`, creates no recovery action, consumes no tool slot, and evaluates state so far. Genuine `ModelProviderError` failures use `PROVIDER_UNAVAILABLE`; invalid client return types, incoherent captured parse metadata, and deterministic-environment rejection after successful runtime validation use `IMPLEMENTATION_BUG`. The engineering runner retains an original-generation provider failure as its scheduled slot, performs no retry, and continues the unconditional 16-slot schedule. Arm traces preserve behavioral versus infrastructure errors and propagate infrastructure exclusion symmetrically within the affected pair. |
| INV-14 | Each original attempt freshly constructs the complete immutable two-message request and invokes the stateless client once. Regeneration likewise starts from the supplied immutable canonical context and builds each continuation from only that arm's explicit assistant/tool history. Repeated-attempt and matched-world tests assert no prior-session state enters requests. Cross-trial trace canary reconciliation remains pending. |
| INV-15 | The immutable catalog contains exactly the eight frozen scenarios and their exact materialized tasks in protocol order. Lookup rejects unknown IDs, and catalog/manifest validation rejects modified values or a task from another scenario under a known ID. The task spec requires non-empty printable-ASCII scenario values, rejects controls and embedded double quotes, and validates the stored `user_task` against those exact fields and the frozen task template without replacing it. The one-shot boundary then requires exactly one function `create_ticket` call, a non-empty provider call ID, strict duplicate-rejecting JSON, the exact three non-empty string fields, and exact task values before freezing M. Every readable ineligible case returns a pre-treatment behavioral result and never reaches family construction; the scheduled-attempt ledger retains its reason and raw response/rejection evidence with zero arm links. |
| INV-16 | Original generation and Regeneration import the same immutable `FROZEN_SYSTEM_MESSAGE` and `FROZEN_TOOL_CATALOG`. Original requests contain exactly system then the validated stored `user_task`, transmitted unchanged, with no assistant, ambiguity, state, or metadata message; tests prove task/template coherence and that model/sampling changes do not alter those messages or tools. A shared immutable provider-neutral model-visible tool-call type represents both original and recovery assistant history; a pure Groq-mapper continuation test preserves exact recovery argument strings, provider order, and observation call-ID linkage without schema changes. |
| INV-17 | A successful Exact Replay result fixes attempted/executed recovery calls at one. The bounded Regeneration executor independently tracks zero-based model invocations and up-to-three in-budget tool attempts, processes multiple requests from one response in provider order without reinvocation, permits one final model call after action three, records only the first over-budget request as `BUDGET_REJECTED_TOOL_CALL`, and leaves later raw calls only in the preserved response. Tests cover three/four/six requests in one response, one request per invocation through index 3, final text, final rejection, and exact no-retry call counts. |
| INV-18 | The builder has no timing input and the canonical logical context permits only frozen messages/tools. Transport timeout exists only on `GroqModelClient` construction and cannot enter `ModelRequest` or the context hash. Executor instrumentation records family-construction, recovery-wall, model, and tool durations only on immutable evaluator-side results, and the trace mapper places them only in the schema's top-level `latency` object. |
| INV-19 | The pure immutable manifest layer materializes the exact 16-slot engineering queue into `ScheduledTrialPlan` values using `hidden_world_order_seed=0`, scenario-derived policy orientation with `policy_order_seed=0`, and the frozen precedence. It validates exact complete-manifest H0/H1 balance, per-world policy balance, per-scenario-by-world replicate balance, 8/8 Replay/Regeneration balance at every absolute family-arm position, and four slots in each A/B/C/D stratum. The runner consumes those entries serially in index order, executes every slot exactly once, and never stops, extends, replaces, resamples, or retries based on eligibility. Its immutable summary requires at least eight eligible families and at least one eligible family in A/B/C/D while retaining all eligible families. Persistence recomputes every eligible family's invariants from retained execution evidence before recomputing the summary; it also recomputes the manifest hash, requires exact entry-by-entry result coherence, and rejects mixed or forged bundles before creating a temporary directory. The atomic bundle's frozen `manifest_kind: engineering_validation`, joined through the manifest ID persisted in every ledger and arm record, unambiguously labels these traces outside paper-result denominators. Tests cover 7, 8, and 16 eligible families, covered and missing-stratum eights, hostile bundle/summary/invariant-cache mismatches, immutable-evidence inconsistencies, and engineering-stage trace linkage. |
| INV-20 | Golden evaluator fixtures cover every primary class, overlaps, precedence, and exact matching; Exact Replay and Regeneration add H0 `CORRECT`/`MISSING_EFFECT`, H1 `DUPLICATE_EFFECT`/`CORRECT`, changed-argument `WRONG_MUTATION`, and infrastructure-precedence state oracles. |
| INV-21 | The adapter preserves every returned tool call in provider order, exact raw `function.arguments`, assistant content, and invalid IDs as readable evidence. Original generation and Regeneration independently verify strict parse coherence and never repair malformed/duplicate-key JSON, select one call from many, or reprompt invisibly. Regeneration invalid types/IDs/tools/shapes consume one slot and terminate without execution or fabricated observation; rejected-generation evidence is never interpreted as a tool action. Recovery continuation history uses the declared shared model-visible type with no type-ignore or canonicalization workaround. Schema-valid changed CREATE arguments remain natural executable behavior as frozen by the drift/evaluator protocol. |
| INV-22 | Model-visible CREATE/LIST projections contain only frozen visible fields. Regeneration tests prove successful CREATE omits ticket IDs and LIST omits ticket/event/state/arm metadata while preserving duplicate multiplicity. |
| INV-23 | Recovery-arm serialization joins both arms before mapping evaluation. Any frozen infrastructure exclusion reason from either arm is applied to both trace evaluations, while the original immutable executor results remain unchanged. Tests validate both affected traces and their shared exclusion reason against the frozen schema. |
| INV-24 | H0 and H1 originate from one captured initial snapshot; each post-ambiguity snapshot is cloned twice without redispatch. The one-trial orchestrator captures immutable pre-policy construction evidence before executing those four clones and keeps their mutable environments execution-local. Tests prove policy execution cannot change the captured initial/world/arm-start bytes or hashes. |
| INV-25 | Eligible and behavioral original-generation results retain exact immutable request/response provenance. Exact Replay records its action/observation/commit/final-state boundary. Regeneration returns every attempted model request with ordinal and derived config, every complete successful `ModelResponse`, rejected/provider failure evidence, ordered processed actions, validation/execution/observation evidence, bounded counters, termination, final snapshot/hash, and deterministic evaluation. The pure trace mapper reconciles zero-based invocation indexes with strictly ordered action indexes and emits their true model/tool interleaving, retains malformed raw `arguments_json`, preserves later unprocessed budget calls in the complete raw response only, and maps rejected-generation evidence without manufacturing an action. Before any temporary output directory is created, production persistence self-validates the frozen Draft 2020-12 schema and validates every arm trace with format checking plus the required RFC 3339 timestamp guard. Tests cover interleaving, multiple actions from one response, all 64 all-eligible traces, malformed/rejected/budget evidence, invalid date-time rejection, and schema-validation cleanup. |
| INV-26 | Original generation parses the captured raw argument string strictly, checks it against captured parse metadata and exact task values, builds one historical assistant message from the raw fields, and separately derives canonical executable M from validated logical arguments plus the identical provider call ID. The eligible result validates request/response/history/M coherence. Tests prove raw formatting changes history and Regeneration hashes while leaving executable bytes/hash equal, and prove call-ID changes alter executable identity. Every arm trace is mapped from those same immutable history, executable bytes/hash, ambiguity linkage, and context-hash objects. |
| INV-27 | Model configuration is a separate immutable value. The Regeneration executor copies the caller's frozen config per call and applies `base_seed + model_call_index`, with null propagating to null. Tests prove indexes/seeds 0..3, H0/H1 equality at shared ordinals, independence from arm identity and multiple actions per response, preservation of every non-seed field, and caller-config integrity. Seeds remain only best-effort provider controls. |
