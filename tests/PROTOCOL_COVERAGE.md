# Implemented invariant coverage

This implementation deliberately covers only invariants enforceable at the
deterministic environment, hidden-world construction, Exact Replay, evaluator,
canonical Regeneration-context, original-generation, and one-call
provider-adapter layers.

| Invariant | Current enforcement |
| --- | --- |
| INV-1 | The original-generation boundary performs one explicit model call and, only for an eligible response, creates one immutable `FrozenExecutableRequest`. Its success object feeds that same M object/bytes/hash directly into family construction, which gives it to all four arm starts. The Regeneration context consumes the simultaneously frozen original assistant message, including its exact raw JSON argument string, without replacing it. Full runner/trace family linkage remains pending. |
| INV-2 | Each hidden-world snapshot is serialized once and cloned into byte/hash-identical, independent policy-arm starting environments; family validation checks both pairs before recovery, and Exact Replay tests prove P1 execution leaves the P2 sibling unchanged. |
| INV-3 | The pure Regeneration context builder accepts only the exact user task, frozen M, and stored original assistant message; it fixes the complete four-message sequence and two-tool catalog. Eligible original-generation output supplies those artifacts directly. The pure boundary helper and Groq mapper prove that H0/H1 yield equal canonical bytes/hashes, equal provider-neutral requests, and equal Groq payloads under the same call configuration while authoritative state hashes differ. |
| INV-4 | Exact Replay has no model parameter, callback, interface, or dependency and its immutable result fixes `additional_llm_calls=0`. Later full traces will reconcile this with lifecycle instrumentation. |
| INV-5 | The canonical context has an exact closed structure and is constructed without a hidden-world or environment input. The provider-neutral helper accepts only that context plus call configuration, and the Groq mapper accepts only the resulting request. Hostile serialized-payload tests scan for hidden labels, execution flags, evaluator classifications and IDs, mutation/state fields, and actual family state hashes. Later runner/trace integration must enforce use of this boundary. |
| INV-6 | Exact Replay passes the post-termination authoritative `TicketState` to the existing deterministic evaluator; no model claim or observation enters evaluation. |
| INV-7 | Family construction requires the fresh empty authoritative state, captures it without mutating the source, and creates every branch/arm by snapshot deserialization. |
| INV-8 | Ticket and immutable event are published atomically; Exact Replay requires one newly committed event, returns its ID, and verifies that event's frozen bytes/hash and RECOVERY provenance. Events remain state-reconstructable. |
| INV-9 | The local executor has no retry/network layer; Exact Replay contains one executor call. The Groq adapter constructs the official SDK with `max_retries=0` and the original-generation attempt contains exactly one `ModelClient.complete` call with no loop, fallback, repair, or resampling. Tests cover eligible, ineligible, rejected-generation, and provider-timeout paths at one invocation. Provider-internal behavior outside the SDK boundary must still be accounted for in experiment traces. |
| INV-10 | Exact Replay verifies SHA-256 and representation equality before dispatch, then passes the caller-supplied `serialized_original_request` bytes object directly to the executor. A capture test proves object identity; parsing for evaluation occurs only after dispatch and is never reserialized. |
| INV-11 | Timeout, authentication, rate-limit, connection, unrelated HTTP 400, 5xx, and structurally malformed-response failures have explicit provider/infrastructure exception types and propagate through original generation. Groq rejected-generation evidence becomes an immutable `REJECTED_GENERATION` pre-treatment behavioral result with diagnostics preserved. No call, multiple calls, invalid call type/ID, wrong tools, malformed JSON, invalid shape, and task-incorrect arguments are closed-taxonomy behavioral results retaining the complete readable response. Full experiment exclusion classification remains pending. |
| INV-14 | Each original attempt freshly constructs the complete immutable two-message request and invokes the stateless client once. Repeated-attempt tests assert neither request contains prior assistant history and the client retains no session object. Cross-trial trace canary reconciliation remains pending. |
| INV-15 | The task spec requires non-empty printable-ASCII scenario values, rejects controls and embedded double quotes, and validates the stored `user_task` against those exact fields and the frozen task template without replacing it. The one-shot boundary then requires exactly one function `create_ticket` call, a non-empty provider call ID, strict duplicate-rejecting JSON, the exact three non-empty string fields, and exact task values before freezing M. Every readable ineligible case returns a pre-treatment behavioral result and never reaches family construction; frozen scenario-catalog membership and scheduled-attempt logging remain pending. |
| INV-16 | Original generation and Regeneration import the same immutable `FROZEN_SYSTEM_MESSAGE` and `FROZEN_TOOL_CATALOG`. Original requests contain exactly system then the validated stored `user_task`, transmitted unchanged, with no assistant, ambiguity, state, or metadata message; tests prove task/template coherence and that model/sampling changes do not alter those messages or tools. The Groq mapper wraps those definitions without schema changes. |
| INV-17 | A successful Exact Replay result fixes attempted/executed recovery calls at one, the implementation has no loop or fallback, and dispatch-delta plus injected-error tests cover success and failure boundaries. The Regeneration budget remains pending. |
| INV-18 | The builder has no timing input and the canonical logical context permits only frozen messages/tools. Transport timeout exists only on `GroqModelClient` construction and cannot enter `ModelRequest` or the context hash. Hostile request-payload tests scan timing and state metadata; runtime diagnostic trace separation remains pending. |
| INV-20 | Golden evaluator fixtures cover every primary class, overlaps, precedence, and exact matching; Exact Replay adds the H0 `CORRECT` and H1 `DUPLICATE_EFFECT` state oracles. |
| INV-21 | The adapter preserves every returned tool call in provider order, exact raw `function.arguments`, assistant content, and a missing ID as readable evidence. The original-generation boundary independently verifies strict parse coherence, never repairs malformed/duplicate-key JSON, never selects among multiple calls, and never reprompts. Wrong tools, invalid types/IDs/shapes, task errors, and rejected generations terminate as the original behavioral outcome after one call. Other provider failures remain typed infrastructure exceptions. |
| INV-22 | Model-visible CREATE/LIST projections contain only frozen visible fields. |
| INV-24 | H0 and H1 originate from one captured initial snapshot; each post-ambiguity snapshot is cloned twice without redispatch. Executing both P1 arms leaves both P2 arms and all stored initial/world snapshot bytes unchanged. |
| INV-25 | Eligible and behavioral original-generation results retain the exact immutable request plus response provenance; rejected-generation results retain failed-generation evidence and provider diagnostics. Eligible results additionally retain the historical assistant message and M bytes/hash. Exact Replay records its action/observation/commit/final-state boundary. Complete lifecycle events, attempt logs, and schema-valid arm traces remain pending. |
| INV-26 | Original generation parses the captured raw argument string strictly, checks it against captured parse metadata and exact task values, builds one historical assistant message from the raw fields, and separately derives canonical executable M from validated logical arguments plus the identical provider call ID. The eligible result validates request/response/history/M coherence. Tests prove raw formatting changes history and Regeneration hashes while leaving executable bytes/hash equal, and prove call-ID changes alter executable identity. Full-trace coherence remains pending. |
| INV-27 | Model configuration is a separate immutable value. Tests prove a seed change changes only model-call configuration/provider fields, not canonical context bytes/hash, and prove identical H0/H1 contexts plus one shared configuration yield equal provider-neutral requests and Groq payloads. Matched multi-call seed derivation and trace enforcement remain pending with Regeneration execution. |
